# 绑定域名与自动 HTTPS

乐云可以自己去 Let's Encrypt 申请免费证书，并在到期前自动续期。
超管后台填个域名就行，不用装 certbot、不用写 cron、不用碰 Nginx 配置。

---

## 先确认这两件事

**不满足的话一定申请不下来**，而且要等几十秒才收到一句看不懂的报错。

### 1. 域名已经解析到这台服务器的公网 IP

```bash
ping pan.example.com          # 看到的 IP 要和服务器的公网 IP 一致
dig +short pan.example.com    # 或者用 dig
```

刚改完解析的话等几分钟——DNS 生效需要时间。

### 2. 80 和 443 端口对公网开放

证书签发机构要**主动从外网访问这两个端口**来验证域名确实归你。

云服务器上这通常意味着两件事都要做：

- 云控制台的**安全组**放行 80、443
- 服务器系统的**防火墙**也放行（`ufw` / `firewalld` / `iptables`）

```bash
# 从外网确认端口通不通（在另一台机器上执行）
curl -I http://pan.example.com
```

还要确认这两个端口没被别的程序占着：

```bash
ss -lntp | grep -E ':80 |:443 '
```

> **如果乐云跑在 Nginx / Caddy / 云负载均衡后面**，证书通常由它们来管，
> 这一页可以完全不用开。同时让两边都去抢 80 端口只会互相打架。

## 配置步骤

超级管理员 → 左侧「域名与 HTTPS」：

1. **域名**：一行一个，也可以逗号分隔。只会为这里列出的域名签发证书。
2. **联系邮箱**：证书将到期而续期又一直失败时，签发机构会往这里发提醒。建议填。
3. **先用测试环境**：第一次配建议**打开**。理由见下一节。
4. **勾选服务条款**：ACME 协议要求明示同意，不勾不能申请。
5. **启用 HTTPS** → 保存。
6. 点「**立即申请 / 续期**」，等结果。

保存后如果是首次启用，需要**重启一次服务**（或重新执行 `./update.sh`）
才会真正开始监听 443 端口——监听要在进程启动时建立。页面上会提示这一点。

### 为什么建议先用测试环境

Let's Encrypt 的正式环境有**频率限额**：同一个域名每周只能签发有限次数。
解析没生效、端口没开这类问题试错几次，就可能被锁一个星期，
到时候真配好了也签不出来。

测试环境没有这个限制。调通之后关掉开关，再正式申请一次即可。
测试环境签出来的证书浏览器不认（会报不安全），这是正常的。

## 验证与日常

配好之后：

- 浏览器访问 `https://你的域名` 应该看到锁图标
- 开了「HTTP 跳 HTTPS」的话，访问 `http://` 会自动跳转
- 管理页面的证书列表显示签发机构、到期时间和剩余天数

证书有效期 90 天，**系统会在到期前 30 天自动续期**，不需要人工操作。
页面上的「立即申请 / 续期」只是在想马上确认结果时才用得上。

---

## 排错

页面上的「最近一次申请失败」会把原因翻成中文。常见的几种：

| 报错里提到 | 怎么办 |
| --- | --- |
| 解析没查到 / NXDOMAIN | 域名还没解析到这台机器，或解析没生效。用 `dig` 确认后再试 |
| 签发机构访问不到本机 | 80/443 没开，或被别的程序占了。安全组和系统防火墙都要查 |
| 触发了频率限额 | 等一小时再试；调试阶段务必先用测试环境 |

其它情况：

**填了域名但保存报错**
IP 地址、`localhost`、`.local` / `.internal` / `.lan` 这类内网域名，
签发机构不会为它们签发证书，所以保存时就挡住了。
内网部署请用自签证书或在反向代理上配置。

**启用了但还是 http**
首次启用需要重启服务。重启后如果还不行，看日志里有没有
"HTTPS 监听失败"——多半是 443 被占用，或者进程没有绑定 1024 以下端口的权限。

**上了 https 之后在线编辑打不开**
浏览器控制台里通常是这句：

```
Mixed Content: The page at 'https://你的域名/office/4/5' was loaded over HTTPS,
but requested an insecure script 'http://1.2.3.4:8081/web-apps/.../api.js'.
This request has been blocked.
```

页面走 https，而编辑器脚本来自 http，浏览器按混合内容规则直接拦掉了。

新版不会出现这个问题：编辑器默认从 `/onlyoffice` 加载，是一个同源路径，
由乐云转发到 Document Server——页面是什么协议它就是什么协议，永远不会错配。
老部署的 `.env` 里即使还写着 `http://IP:8081`，页面走 https 时乐云也会发现
这个组合注定被拦，自动改用同源转发，并在日志里写明原因。

想彻底干净的话，把 `.env` 里那一行改成：

```bash
LEYUN_OFFICE_PUBLIC_URL=/onlyoffice
```

再 `./update.sh --no-pull`。改完之后 8081 也不必再暴露到公网了。

**Docker 部署**
`./deploy.sh` 默认就会映射 80 和 443，不用改任何东西。

它在部署前会先看这两个端口是否空闲：

- 空闲 → 正常映射，收尾信息里会提示"可以去填域名了"
- 被别的服务（Nginx 之类）占着 → **自动降级**到 18080/18443 并给出提示。
  网盘照常可用，只是内置的自动证书这条路走不通，应当改由前面那层反向代理管证书。

也可以用 `./deploy.sh --no-https` 主动不占这两个端口。

降级之后想改回来：确认 80/443 已经空出来，重跑 `./deploy.sh` 即可
（它会重新检测并写回 .env）。或者手工改 `.env` 里的
`LEYUN_HTTP_PORT` / `LEYUN_HTTPS_PORT` 再 `./update.sh --no-pull`。

## 它是怎么做的

用的是 Go 官方的 `golang.org/x/crypto/acme/autocert`。选它而不是自己实现 ACME，
是因为申请、缓存、到期自动续期它都做好了，而且 `x/crypto` 本来就是乐云的依赖，
引它不增加任何新的外部依赖。

两个值得一提的实现细节：

**只为绑定的域名签发**。不加这道限制的话，任何人把自己的域名解析到这台机器，
就能让它去替对方申请证书——很快会撞上频率限额，把真正要用的域名一起卡住。

**状态页不会触发签发**。证书状态是直接读缓存的，不是调"取证书"接口。
后者在没有证书时会当场去申请，而状态页会被反复刷新，那样每刷一次就可能
打一次签发机构。

证书和 ACME 账号私钥存在 `data/certs/` 下，会跟着 `./update.sh` 的备份一起打包。
这是有意的：恢复之后证书还在，不用重新申请，省得撞上那个"每周只能签几次"的限额。
也因此，**备份文件本身要按私钥的标准保管**。
